# 카이토리 유저 거래 매물 탐색기 기획

## 1. 제품 방향

현재 프로젝트의 이름은 `유저 거래가 수집기`지만, 확장 방향은 단순 가격 수집보다 넓다.

> 공개 거래글을 모아 카드별 판매 매물과 구매 수요를 연결하고, 지금 어떤 카드가 시장에 나와 있으며 어떤 카드가 필요로 되는지 보여주는 탐색기

이 제품은 거래를 직접 중개하지 않는다. 공개 게시글을 읽어 다음 정보를 정리한다.

- 어떤 카드가 판매 중인가
- 어느 가격대에 판매되고 있는가
- 어떤 카드의 구매글이 올라오고 있는가
- 판매 매물과 구매 수요가 서로 만날 가능성이 있는가
- 게임·카드·기간별 거래 분위기가 어떻게 변하는가

핵심 사용자는 세 부류다.

1. 카드를 보유한 사람: 내가 가진 카드의 구매 수요가 있는지 확인한다.
2. 카드를 찾는 사람: 원하는 카드의 판매 매물을 빠르게 찾는다.
3. 운영자·샵: 유저 거래가와 수요 변화를 참고해 매입가와 재고 우선순위를 정한다.

## 2. 핵심 화면

### 2.1 매물 탐색

첫 화면은 크롤러 실행 화면이 아니라 검색 화면이어야 한다.

검색 조건:

- 게임
- 카드명 또는 카드 코드
- 판매 / 구매 / 교환 구분
- 가격 범위
- 최근 등록 기간
- 레어도·세트·상태

결과 카드에는 다음을 표시한다.

- 카드명과 매칭 신뢰도
- 판매 매물 수
- 구매글 수
- 관측된 판매가 범위와 중앙값
- 가장 최근 게시 시각
- 원문으로 이동
- `구매 수요 있음`, `판매 매물 부족`, `가격 편차 큼` 같은 상태 배지

### 2.2 카드 상세

카드 하나를 선택하면 판매와 구매를 같은 화면에서 비교한다.

```text
카드명 / 게임 / 세트 / 레어도

판매 매물  12건       구매 수요  7건
판매가     28,000~35,000원
중앙값     31,000원
최근 등록  2시간 전

[판매 매물] [구매 수요] [가격 추이]
```

판매 매물에는 유저가·수량·배송비·원문 링크를 표시하고, 구매 수요에는 희망 가격·필요 수량·원문 링크를 표시한다. 가격이 없는 `구해요` 글도 수요 표본으로 보존한다.

### 2.3 보유 카드 수요 탐색

사용자가 보유 카드를 입력하거나 카탈로그에서 선택하면 다음을 보여준다.

- 최근 구매글이 있는 카드
- 구매글 수가 갑자기 증가한 카드
- 판매 매물은 적고 구매 수요가 많은 카드
- 구매자 희망가가 최근 판매가와 가까운 카드

이 화면의 핵심 문구는 `이 카드를 사려는 공개 글이 있습니다`다. 단, 특정 이용자에게 연락을 자동으로 보내거나 거래를 성사시키지는 않는다.

### 2.4 거래 동향

기간과 게임을 선택해 다음 지표를 본다.

- 판매글 수 / 구매글 수
- 카드별 수요 점수
- 평균가보다 중앙값을 우선한 가격 변화
- 신규 카드·재록 카드의 수요 변화
- 판매 매물 대비 구매 수요 비율
- 거래글이 급증한 카드
- 매물이 사라지는 카드

초기에는 복잡한 금융 차트보다 카드별 표와 간단한 선 그래프가 적합하다.

## 3. 게시글 분류 체계

현재는 게임별로 `판매`, `거래`, `🔁거래` 말머리를 사용한다. 확장 후에는 말머리와 본문을 함께 사용해 거래 의도를 분류한다.

```text
listing_type
├─ sell       판매합니다 / 팝니다
├─ buy        구합니다 / 구해요 / 구매합니다
├─ trade      교환합니다 / 교환 구해요
└─ unknown    의도 판별 실패
```

게임별 기본 설정은 유지한다.

| 게임 | 목록 말머리 | 기본 의도 |
|---|---|---|
| 유희왕 | 판매 | sell |
| 원피스 카드게임 | 판매 | sell |
| 포켓몬 카드게임 | 🔁거래 | trade 또는 본문에서 buy/sell 분류 |
| 디지몬 카드게임 | 거래 | trade 또는 본문에서 buy/sell 분류 |
| 뱅가드 | 거래 | trade 또는 본문에서 buy/sell 분류 |

`거래` 말머리는 판매와 구매가 섞일 수 있으므로, 말머리만 보고 판매글로 저장하면 안 된다. 제목·본문에서 다음 표현을 별도로 추출한다.

- 판매 신호: `팝니다`, `판매`, `처분`, `일괄`, `택포`
- 구매 신호: `구합니다`, `구해요`, `삽니다`, `구매`, `찾습니다`
- 교환 신호: `교환`, `트레이드`, `원합니다`

신호가 충돌하거나 없으면 `needs_review`로 남긴다.

## 4. 판매·구매 매칭

판매글과 구매글을 단순히 카드명 문자열로만 연결하지 않는다. 다음 단계로 정규화한다.

1. 카드 코드 추출
2. 카드명·게임·세트·레어도 후보 추출
3. 수량과 가격 추출
4. 상태·언어·판본 후보 추출
5. 카드 카탈로그와 매칭
6. 매칭 신뢰도에 따라 자동 연결 또는 검토 대기

카드별 수요 상태는 다음처럼 계산한다.

```text
demand_status
├─ hot_demand       최근 구매글이 많고 판매 매물이 적음
├─ balanced         판매와 구매가 모두 관측됨
├─ supply_heavy     판매 매물이 많고 구매글이 적음
├─ stale_demand     구매글은 있으나 오래됨
└─ unknown          카드 매칭 또는 날짜 정보 부족
```

수요 점수의 초기 버전은 설명 가능한 단순식으로 시작한다.

```text
demand_score
= 최근 7일 활성 구매글 수
  × 최근성 가중치
  × 매칭 신뢰도
  ÷ max(판매 매물 수, 1)
```

점수만 보여주지 말고 반드시 근거를 같이 보여준다. 예: `최근 7일 구매글 6건 / 판매 매물 2건`.

## 5. 데이터 모델 확장

기존 `ExtractedRow`는 하위 호환을 위해 유지하고, 새 탐색기용 표준 레코드를 별도로 둔다.

### `kaitori_listings`

- `id`
- `source_id`
- `gallery_id`
- `game_id`
- `listing_type`: `sell|buy|trade|unknown`
- `intent_confidence`
- `card_name_raw`
- `card_id`
- `card_code`
- `rarity`
- `set_name`
- `condition_raw`
- `price_krw`
- `price_type`: `asking|wanted|unknown`
- `quantity`
- `shipping_included`
- `review_status`
- `review_reason`
- `raw_line`
- `created_at`
- `updated_at`

### `kaitori_demand_snapshots`

카드별 동향을 매번 원문에서 다시 계산하지 않도록 일 단위 집계를 저장한다.

- `snapshot_date`
- `game_id`
- `card_id`
- `sell_count`
- `buy_count`
- `trade_count`
- `sell_price_median`
- `sell_price_min`
- `sell_price_max`
- `wanted_price_median`
- `active_source_count`
- `demand_score`

### 원문 보존과 개인정보

- 원문 URL과 원문 HTML은 운영자만 접근
- 사용자명·전화번호·계좌번호·오픈채팅 링크는 공개 결과에서 제거
- 분석 레코드에는 필요한 거래 정보만 남김
- 삭제·수정된 글은 `source_status`로 표시

## 6. 수집 파이프라인

```text
게임별 프리셋
  → 목록 말머리 수집
  → 최근 기간 필터
  → 게시글 원문 보존
  → 판매/구매/교환 의도 분류
  → 카드·가격·수량 추출
  → 카탈로그 매칭
  → needs_review
  → 일별 동향 집계
  → 탐색 화면·CSV·운영 지표
```

이미지 전용 글은 현재처럼 텍스트 파싱 결과를 억지로 만들지 않는다.

- `image_only` 상태로 보존
- 원문 링크 제공
- OCR 도입 전까지 수동 검토 대상으로 분리

## 7. 단계별 출시 계획

### 1단계: 거래 의도 수집

- `buy`·`trade` 말머리 설정 추가
- `거래` 말머리의 판매/구매/교환 분류
- 구매글에서 카드명·수량·희망가 추출
- 판매·구매를 같은 카드 ID로 연결
- 카드별 `판매 매물 수 / 구매글 수` 표시

완료 기준:

- 판매·구매·교환이 섞인 글을 자동 확정하지 않음
- 구매글의 희망가가 없더라도 수요 표본으로 저장
- 동일 카드의 판매·구매 결과를 한 화면에서 조회

### 2단계: 매물 탐색기

- 게임·카드명·거래 유형 검색
- 최근 등록순·가격순·수요순 정렬
- 원문 링크와 게시 시각 표시
- 7일·30일 필터
- 결과 CSV 내보내기

### 3단계: 동향 분석

- 일별 스냅샷
- 카드별 가격 중앙값·표본 수
- 수요 점수
- 급증·급락 감지
- 게임별 거래량 비교

### 4단계: 보유 카드 수요 탐색

- 보유 카드 목록 입력·CSV 불러오기
- 구매 수요가 있는 카드만 필터
- 수요 강도와 근거 표시
- `판매할 만한 카드` 후보 목록 생성

### 5단계: 운영 시스템 연결

- 승인된 유저가를 매입가 산정에 반영
- 매입가 변경 전 미리보기
- 가격표 반영 이력
- 자동 반영은 별도 승인 뒤 실행

## 8. 우선순위가 낮은 기능

처음부터 다음 기능은 넣지 않는다.

- 사이트 내 로그인
- 게시글 작성·댓글·DM
- 자동 거래 중개
- 판매자·구매자 평판 점수
- 전화번호·계좌번호 수집
- 이미지 OCR 자동 확정
- 복잡한 AI 가격 예측

이 제품의 강점은 거래를 대신하는 것이 아니라, 흩어진 공개 거래 신호를 카드 단위로 정리해서 `무엇이 팔리고 무엇이 필요한지` 빠르게 보여주는 데 있다.

## 9. 첫 번째 실제 사용 시나리오

1. 운영자가 최근 7일 데이터를 수집한다.
2. 사용자가 보유 카드 `블루아이즈 울레`를 검색한다.
3. 화면에 판매 매물 2건, 구매글 6건이 표시된다.
4. 최근 구매글의 희망가는 28,000원~32,000원으로 나타난다.
5. 사용자는 수요가 있다는 것을 확인하고 원문 게시글을 직접 열어 거래 여부를 판단한다.
6. 운영자는 같은 데이터를 매입가 검토와 가격 동향 분석에 사용한다.

## 10. 제품 한 줄 정의

> 카드를 가진 사람에게는 어디서 수요가 생기는지 보여주고, 카드를 찾는 사람에게는 어디에 매물이 있는지 보여주는 공개 유저 거래 탐색기.
