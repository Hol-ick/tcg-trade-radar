# 카드 거래 동향 분석 고도화 구현 계획

> **실행 에이전트용:** 이 계획은 현재 세션에서 바로 실행한다. 각 작업은 테스트를 먼저 추가하고 구현한 뒤 검증한다.
**목표:** 수집된 판매글·구매글을 카드 단위로 안정적으로 묶고, 어떤 카드에 수요가 몰리는지와 관측된 가격대를 탐색기에서 바로 확인할 수 있게 한다.
**구조:** 기존 수집·원문 보존 구조는 유지한다. 조회 시 보수적인 카드명 정규화를 적용하고, 거래 유형별 글 수·게시글 수·최근성 가중 수요 점수·데이터 신뢰도를 계산한다. 스냅샷은 새 지표를 저장해 날짜별 비교에 사용한다.
**기술 스택:** Python 3.11, SQLite, tkinter, 기존 unittest 및 실제 DCInside 수집 스크립트

## 공통 제약

- 공개 게시글 수집 범위와 기존 개인정보 최소 수집 원칙을 유지한다.
- 원문 `card_name_raw`와 원문 링크는 보존하되, 정규화된 이름은 분석용으로만 사용한다.
- 카드 카탈로그가 없는 상태에서도 분석 가능해야 하며, 애매한 이름을 공격적으로 합치지 않는다.
- 가격이 없는 구매글도 수요 건수에는 포함하고, 가격 중앙값에는 포함하지 않는다.
- 기존 API 필드와 기존 화면 흐름을 깨지 않고 새 필드를 추가한다.
- `.audit`, SQLite 샘플 DB, 인증정보는 Git에 올리지 않는다.

## 작업 1: 카드명 정규화 경계와 테스트 작성

**파일:**
- 생성: `kaitori_collector/normalization.py`
- 생성: `tests/test_normalization.py`
- 수정: `kaitori_collector/storage.py`

**구현:**

1. `normalize_listing_card_label(raw_label, listing_type)` 공개 함수를 만든다.
2. 구매·판매 표현, 수량 표현, 가격 꼬리표, 괄호 안 거래 메모처럼 카드 식별에 직접 필요 없는 토큰만 제거한다.
3. 카드 코드가 있으면 코드의 대소문자·구분자를 정리하고, 일반 카드명은 공백과 구두점만 안정적으로 정리한다.
4. 정규화 결과가 지나치게 짧거나 거래 표현만 남으면 원문을 유지하고 `needs_review` 성격의 품질 신호를 반환할 수 있도록 작은 데이터 구조를 둔다.
5. `summarize_cards`의 그룹 키를 `card_code` 우선에서 `정규화 카드명/코드` 기준으로 바꾸고, 화면 표시용 원문은 대표값으로 유지한다.

**테스트 우선:**

- `"골디온 2장 0.6"`에서 수량·가격 꼬리표를 제거한다.
- `"삼영의 상검사 산다이온 구합니다"`와 판매 제목이 같은 정규화 키로 연결된다.
- 실제 카드명에 포함된 숫자·영문 코드는 보존한다.
- 빈 문자열과 거래 표현만 있는 입력은 잘못된 카드명으로 합치지 않는다.

**검증:** `python -m unittest tests.test_normalization -v`

## 작업 2: 카드별 공급·수요 지표 고도화

**파일:**
- 수정: `kaitori_collector/storage.py`
- 수정: `tests/test_market.py`

**구현:**

1. 기존 판매·구매·교환 건수에 더해 `sell_post_count`, `buy_post_count`, `sell_quantity`, `buy_quantity`, `recent_sell_count`, `recent_buy_count`를 계산한다.
2. 같은 게시글 안의 여러 행은 글 수와 매물 행 수를 구분해 중복 과대평가를 줄인다.
3. 최근성은 게시 시각을 기준으로 7일 이내를 1.0, 8~30일을 0.5, 그 이전을 0.25로 가중한다. 날짜가 없는 행은 기존 건수에는 포함하되 최근성에는 넣지 않는다.
4. `demand_score`는 설명 가능한 형태로 `최근 구매 가중치 / max(최근 판매 가중치, 1)`로 계산하고, `demand_ratio`도 함께 반환한다.
5. `demand_status`는 구매 우세·균형·판매 우세·오래된 수요·확인 필요로 구분한다. 최소 표본 수가 작은 구매글은 `confidence`와 `quality_status`로 표시한다.
6. 근거 문구에는 최근 구매글, 전체 구매글, 판매글, 관측 가격 범위를 함께 표시한다.

**테스트 우선:**

- 구매 3건·판매 1건이면 구매 우세와 높은 점수가 나온다.
- 오래된 구매글만 있으면 최근 구매 수가 0이고 오래된 수요 상태가 나온다.
- 가격 없는 구매글은 구매 수에는 포함되고 희망가 중앙값에서는 제외된다.
- 동일 게시글의 행이 여러 개여도 post count가 행 수와 다르게 계산된다.
- 반환 dict에 새 분석 필드가 항상 존재한다.

**검증:** `python -m unittest tests.test_market -v`
