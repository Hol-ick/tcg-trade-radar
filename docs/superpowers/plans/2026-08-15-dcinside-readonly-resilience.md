# 디시인사이드 공개 수집 안정화 계획

## 목표

디시인사이드 공개 갤러리 목록·게시글·댓글 수집을 현재 응답 환경에 맞게 안정화한다. 기존 데이터 재사용과 중복 방지 계약은 유지한다.

## 확인된 원인

- `gall.dcinside.com` 목록 요청은 HTTP 200이어도 본문 0바이트로 반환된다.
- 같은 목록을 `m.dcinside.com` 공개 경로로 요청하면 정상적인 HTML과 목록 행을 받을 수 있다.
- 현재 자동 전송 순서는 데스크톱 요청 → 빈 응답 데스크톱 재요청 → 모바일 → 브라우저라서, 이미 실패가 확인된 경로에 요청을 낭비한다.
- 브라우저 폴백은 현재 환경에서 39자짜리 빈 셸을 반환하므로 성공 경로가 아니다.

## 구현 범위

1. 디시인사이드 공개 URL은 모바일 HTTP를 먼저 시도하고, 실패하거나 구조가 맞지 않을 때만 데스크톱 HTTP와 브라우저 폴백을 사용한다.
2. 자동 전송 과정에서 동일한 데스크톱 빈 응답을 즉시 한 번 더 두드리는 동작을 제거한다.
3. 작업 서비스에 호스트별 요청 시작 간격을 두어 상세글 동시 수집이 폭주하지 않도록 한다. 요청 신원 변경, 프록시 회전, CAPTCHA/WAF 우회는 추가하지 않는다.
4. 차단 응답을 감지하면 재시도하지 않고 해당 작업을 중단하며 로그에 중단 이유를 남긴다.
5. 모바일 우선 순서, 데스크톱 폴백, 차단 즉시 중단에 대한 회귀 테스트를 추가한다.

## 안전 경계

- 로그인·아이디·비밀번호·쿠키·세션 토큰을 사용하거나 저장하지 않는다.
- GhostProtocol에서는 공개 읽기 전용 수집에 필요한 파싱·샘플링·관찰성 패턴만 참고하고, 자동화 탐지 우회·User-Agent 회전·CAPTCHA 우회·프록시 회전·대량 병렬화는 복사하지 않는다.
- 게시글 작성, 댓글 작성, DM, 거래 자동화는 수행하지 않는다.

## 검증

- Python 단위/통합 테스트
- `python -B -m compileall` 컴파일 검증
- 실제 공개 디시인사이드 목록 2개 갤러리의 모바일 우선 스모크
- 변경 전후 요청 순서와 응답 상태 로그 확인
